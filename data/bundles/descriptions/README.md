# Bundle descriptions — REVIEW COPY, NOT PUBLISHED

Generated by `node agents/pdp-builder/index.js bundle <handle>`.

Each bundle has two files:

- `<handle>.html` — the proposed Shopify `descriptionHtml`, exactly as it would be pasted in.
- `<handle>.json` — the proposed SEO title and meta description, plus the per-variant
  savings arithmetic the copy was written from.

**Nothing here is live.** `pdp-builder` has no Shopify write path in any mode: it writes the
full queue item to `data/performance-queue/bundle-<handle>.json` for review, and mirrors the
reviewable copy here because that queue directory is gitignored and the text has to travel
with the pull request. Publishing, and any change to a product's `status`, is a human action.

A file only appears here if the run passed every gate: length bounds, competitor/generic term
exclusion, the ingredient-fabrication scan, the health-claim gate
(`agents/ad-studio/health-claims.js`), the component and scent check, the fabricated-size check,
and the savings check. A run that fails leaves the queue item behind with its errors and writes
nothing here.

Every dollar figure in this copy is computed from live Shopify component variant prices at
generation time. If a component price changes, the arithmetic in `<handle>.json` is stale —
re-run the bundle rather than editing the number by hand.

## Why `coconut-bar-soap-4-pack` is not here

It was generated and then deliberately discarded. Unlike the other five, that
product already had a 1,274-character description on Shopify, and the live copy
sells a 4-month refill subscription at 15% off — an angle the generated
replacement did not carry. Keeping the live copy was the better trade.

Do not regenerate and publish it without re-reading what is live first. The
brief that produced this batch asserted all six were empty; that was wrong for
this one, and only checking Shopify caught it.
