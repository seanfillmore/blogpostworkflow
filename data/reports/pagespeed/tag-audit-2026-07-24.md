## On-page tag sources (from live HTML)

1. **Google & YouTube channel pixel** (Shopify Web Pixel Manager) — one pixel multiplexing to `google_tag_ids: [G-PYV4WG2QL8, GT-TBVN96Q, G-12BJ5N9FNX]` plus `AW-10923654107` conversion events (search / view_item / begin_checkout / purchase, each with distinct action labels).
2. **Hardcoded theme.liquid gtag** — `<!-- Google tag (gtag.js) -->` loading `G-PYV4WG2QL8` directly (async). Duplicate of #1.
3. **Hardcoded theme.liquid GTM container** — `GTM-MKJBFZ8M` (`<!-- Google Tag Manager -->` snippet + noscript). Loads gtm.js; internal tags not yet inspected. No independent GA4/Ads config observed in on-page HTML.

## Confirmed issues

1. **GA4 `G-PYV4WG2QL8` double-fires** — from both the channel pixel and the hardcoded theme gtag. Inflates sessions, corrupts engagement/bounce.
2. **Two GA4 properties collecting live in parallel** (`G-PYV4WG2QL8` + `G-12BJ5N9FNX`) — data split across two properties → GA4 reports untrustworthy. This is the concrete cause behind "GA4 lies / true CVR 0.82%."
3. **Google's own diagnostics agree** — the Google tag shows "Tag quality: Needs Attention → sending to multiple destinations," and "Ignore duplicate instances of on-page configuration" is currently **OFF**.

## Explicitly NOT confirmed (evidence-checked)

- **Ads conversion double-counting.** All 7 `AW-10923654107` references are inside the channel pixel config with proper per-event labels. No `gtag('config','AW-…')`, no stray `send_to`, no GTM-fired Ads tag on-page. The single-source Ads path looks correct. The poor historical ROAS (0.19×) is more likely genuinely weak early campaigns + untrustworthy GA4, **not** a measurement double-count.
